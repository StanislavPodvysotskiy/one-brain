# One Brain

[English version](README.md)

**Общая память проектов для всех ваших ИИ-ассистентов – обычные Markdown-файлы, которые принадлежат вам.**

Вы работаете с Claude, Kimi, Qwen, локальной моделью, веб-чатом. У каждого своя история, и при
каждом переходе контекст теряется: что сделано, что решили, что дальше. Потеряете доступ к сервису –
история уйдет вместе с ним.

One Brain переносит эту память из моделей в хранилище Obsidian на вашем диске. Каждая модель читает
состояние проекта перед началом работы и записывает итог в конце. Смените модель посреди задачи или
подключите новую, и она продолжит с последней сохраненной сессии.

```
 Claude Code ─┐                                       ┌─ 10_Projects/Weather Bot/
 Kimi CLI ────┤  глобальное правило: «One Brain»      │    README.md     цель, контекст, стек
 Hermes+Qwen ─┼─ скилл: как читать и записывать  ───► │    STATUS.md     сделано / в работе / дальше
 Codex, … ────┤  brain.py: одна команда на шаг        │    DECISIONS.md  что решили и почему
 веб-чаты ────┘  (скрипты для буфера обмена)          │    sessions/     итог каждой сессии
                                                      └─ 00_Home.md      все проекты на одном экране
```

- **Нет привязки к поставщику.** Markdown-файлы и соглашение [AGENTS.md](https://agents.md). Ни
  MCP-сервера, ни базы данных, ни облака. Если модель завтра исчезнет, память останется у вас.
- **Несколько моделей, одна память.** Передача работы проверена на Claude Code, Kimi Code CLI и
  локальной Qwen 3.5 9B (через Hermes Agent): каждая нашла проект из посторонней папки и правильно
  пересказала его состояние.
- **Работает с маленькими локальными моделями.** `brain.py context` одной командой выдает весь
  контекст проекта, `brain.py save-session` сам выбирает имя файла и шапку. Модели на 9B не нужно
  выполнять протокол из нескольких шагов.
- **Проект находится по папке.** Один раз свяжите проект с папками кода (поле `repo:`), и модель,
  работающая в такой папке, найдет проект сама.
- **Перенос истории.** Промпт, с которым любая модель выгружает все, что знает о ваших проектах из
  своей истории чатов. Сведения дополняют существующие карточки, а не дублируют их.
- **Только дополнение и версии.** Сессии и решения только дописываются, а хранилище – это
  Git-репозиторий, поэтому любую заметку, испорченную моделью, можно восстановить.

## Быстрый старт

Нужны Python 3.8+ (только стандартная библиотека), Git (желательно) и Obsidian (необязательно, это
просто Markdown). Проверено на macOS; на Linux должно работать; на Windows используйте WSL.

```bash
git clone https://github.com/StanislavPodvysotskiy/one-brain.git
cd one-brain
python3 install.py ~/OneBrain
```

Команда создаст хранилище в `~/OneBrain` (с примером проекта) и подключит найденные на компьютере
ИИ-инструменты, подробнее – в разделе [Что меняет установщик](#что-меняет-установщик).

Затем:

1. Откройте `~/OneBrain` в Obsidian как хранилище. Рекомендуемые плагины: **Obsidian Git**
   (автокоммит) и **Dataview** (сводные таблицы на главной странице).
2. Заполните `20_Knowledge/User Profile.md`: кто вы и как вам удобно работать.
3. Спросите любую подключенную модель: *«Какие проекты у меня есть в One Brain?»*

> **Храните свое хранилище приватно.** Этот репозиторий – инструмент, а хранилище – ваши данные. Не
> отправляйте его в публичный репозиторий.

**О языке.** Правила, шаблоны и заголовки разделов в хранилище на английском. Модели отвечают на
вашем языке и понимают команды вроде «закрой сессию» по-русски, заметки и названия проектов можно
вести на русском. Заголовок `## Goal` в README проекта не переводите: по нему `brain.py` находит
цель проекта.

## Повседневная работа

| Что нужно | Что сделать |
|---|---|
| Начать работу над проектом | Просто начните в его папке или скажите *«продолжим проект Weather Bot»*. Модель прочитает README, STATUS, DECISIONS и последние сессии и расскажет, где проект сейчас. |
| Сохранить сделанное | Скажите *«закрой сессию»* (или *«сохрани итог»*). Модель запишет итог сессии и обновит STATUS. |
| Добавить проект | `python3 ~/OneBrain/scripts/brain.py new-project "Название" --repo ~/code/name` или попросите об этом модель. Несколько папок: `--repo "~/code/app, ~/docs/app"`. |
| Работать в веб-чате (без доступа к файлам) | `~/OneBrain/scripts/context-pack.sh "Название"` копирует контекст в буфер обмена, вставьте его в чат. В конце скопируйте итог модели и выполните `scripts/save-session.sh "Название" kimi "тема"`. Если в чате принимались решения, скопируйте их и выполните `scripts/save-session.sh "Название" decisions`. Затем скопируйте новый STATUS и выполните `scripts/save-session.sh "Название" status`. |
| Перенести историю чатов модели | `~/OneBrain/scripts/import-prompt.sh kimi` копирует промпт со списком уже заведенных проектов. Вставьте его в чат этой модели, сохраните ответ в `00_Inbox/`, затем попросите модель с доступом к файлам: *«разнеси 00_Inbox/<файл> по проектам One Brain»*. |

Полный протокол для моделей – в [`template/AGENTS.md`](template/AGENTS.md), сокращенная версия,
которую они загружают как скилл, – в [`skills/one-brain/SKILL.md`](skills/one-brain/SKILL.md).

### Команды `brain.py`

```
list                                   проекты, статус и следующий шаг
find [ПАПКА]                           к какому проекту относится папка
context [ПРОЕКТ|ПАПКА] [-n N] [--web]  README + STATUS + DECISIONS + последние N сессий
save-session ПРОЕКТ МОДЕЛЬ ТЕМА        итог сессии из stdin в sessions/
save-status ПРОЕКТ                     заменить STATUS.md текстом из stdin (история остается в Git)
save-decisions ПРОЕКТ                  новые записи DECISIONS.md из stdin, ставятся в начало
new-project ПРОЕКТ [--repo ПАПКИ]      проект из шаблонов + строка на главной странице
import-prompt [--model ИМЯ]            промпт для веб-чата: выгрузить проекты модели
```

## Поддерживаемые инструменты

Чтобы модель пользовалась хранилищем в любой папке, а не только внутри него, есть три слоя: короткое
**глобальное правило**, которое загружается в каждый разговор, **скилл `one-brain`** с процедурой и
**`brain.py`**, который делает механическую работу.

| Инструмент | Глобальное правило | Скилл | Статус |
|---|---|---|---|
| Claude Code | `~/.claude/CLAUDE.md` | `~/.claude/skills/one-brain` | проверено |
| Kimi Code CLI | `~/.agents/AGENTS.md` | `~/.agents/skills/one-brain` | проверено |
| Hermes Agent (любая модель, например локальная Qwen) | `~/.hermes/SOUL.md` | `~/.agents/skills` через `skills.external_dirs` | проверено с Qwen 3.5 9B |
| Codex CLI | `~/.codex/AGENTS.md` | – (только правило) | настроено, не проверено |
| Gemini CLI | `~/.gemini/GEMINI.md` | – (только правило) | настроено, не проверено |
| Qwen Code | `~/.qwen/QWEN.md` | – (только правило) | настроено, не проверено |
| Любой веб-чат | скрипты для буфера обмена | – | работает с любой моделью |

Внутри хранилища `CLAUDE.md`, `QWEN.md` и `GEMINI.md` только импортируют `AGENTS.md`, поэтому правила
лежат в одном файле. Инструменту, который читает `AGENTS.md`, больше ничего не нужно. Если инструмента
нет в списке, укажите в его глобальных инструкциях путь к `~/OneBrain/global/AGENTS.md`.

## Что меняет установщик

Вне хранилища и только для найденных инструментов:

- добавляет блок между `<!-- one-brain:start -->` и `<!-- one-brain:end -->` в файлы глобальных
  инструкций из таблицы выше (ваше содержимое этих файлов сохраняется);
- копирует скилл в `~/.agents/skills/one-brain` и `~/.claude/skills/one-brain`;
- добавляет `~/.agents/skills` в `skills.external_dirs` в `~/.hermes/config.yaml`.

Для каждого существующего файла один раз создается резервная копия `<файл>.one-brain-backup`. Пути
через символические ссылки и скиллы, которые установил не он, установщик не трогает и сообщает о них.
Запускать его повторно безопасно: он обновит блок и копии скилла, а не продублирует их.

**Обновление:** `git pull && python3 install.py ~/OneBrain`. В существующем хранилище обновляются
только файлы, которыми управляет One Brain (`scripts/`, `skills/one-brain/`, `global/AGENTS.md`).
Ваши заметки не затрагиваются.

**Удаление:** `python3 install.py --uninstall` убирает блоки, копии скилла и запись в Hermes.
Само хранилище никогда не удаляется.

## Структура хранилища

```
AGENTS.md            правила для всех моделей (меняйте под себя)
00_Home.md           все проекты: статус и следующий шаг
00_Inbox/            сырые заметки и выгрузки чатов для разбора
10_Projects/<Имя>/   README.md, STATUS.md, DECISIONS.md, sessions/, artifacts/
20_Knowledge/        знания вне конкретного проекта, ваш профиль
90_Templates/        шаблоны файлов проекта, сессий и переноса истории
99_Archive/          завершенные проекты
skills/, global/, scripts/   управляются установщиком
```

`status` проекта (в шапке `STATUS.md`) принимает одно из значений: `active`, `paused` или `done`.
`save-status` отклоняет любое другое, поэтому сводка на главной странице остается согласованной.

Пример `10_Projects/Example - Weather Bot` показывает заполненную карточку с сессиями двух разных
моделей. Удалите его (и его строку в `00_Home.md`), когда он станет не нужен.

## Почему так устроено

- **Файлы, а не сервер.** Читать и записывать файлы умеет любой агент, MCP – не каждый, а сервер –
  это еще одна вещь, которая должна работать. Obsidian дает интерфейс бесплатно.
- **Один источник правил.** Правила лежат в `AGENTS.md`, а файлы отдельных инструментов только
  ссылаются на него, поэтому они не расходятся.
- **Механику делает утилита.** Маленькие модели хорошо пишут сводки и плохо справляются с учетом из
  нескольких шагов, поэтому поиск проекта, имена файлов и шапка – это код, а не промпт.
- **STATUS короткий, сессии длинные.** STATUS помещается на один экран и переписывается, а сессии и
  решения – история, которая только дополняется.

## Ограничения

- Модели следуют правилам в большинстве случаев, но не всегда. Если модель не сохранила итог,
  скажите *«закрой сессию»*.
- Маленькие локальные модели работают медленно: Qwen 3.5 9B отвечала на вопрос «на чем остановились»
  около 3,5 минуты.
- Две модели, которые одновременно пишут в один проект, могут затереть STATUS друг друга. Работайте
  над проектом одной моделью за раз, Git в любом случае хранит историю.
- Это память, а не поиск: RAG и эмбеддингов нет. Для большой базы знаний посмотрите
  [паттерн LLM Wiki Карпати](https://gist.github.com/karpathy) вместо One Brain или вместе с ним.
